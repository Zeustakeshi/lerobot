# TurboVLA (experimental)

TurboVLA is available as a native, experimental LeRobot policy type. The native
model and serializable data processors support the LIBERO data contract. The released
LIBERO checkpoint has strict conversion/loading and fixed-input raw-action parity
coverage; full benchmark reproduction remains experimental work. RoboTwin is not yet
a validated release path.

```bash
pip install "lerobot[turbovla]"
lerobot-train --policy.type=turbovla --dataset.repo_id=<org/dataset>
```

The dataset must provide the exact TurboVLA state mean/std, action min/max statistics,
and ordered camera features. Runtime inference supplies a non-empty `task` string. See the
[TurboVLA policy page](./policy_turbovla_README.md) for the full processor contract.

## LIBERO evaluation contract

TurboVLA LIBERO checkpoints are evaluated through the standard `lerobot-eval`
entry point. A full comparable run uses the four official suites, 50 trials per
task, seed 7, two cameras (`agentview_image`, `robot0_eye_in_hand_image`),
8-D flattened state
(`eef_pos`, axis-angle orientation, gripper qpos), 7-D relative actions, bf16/AMP,
and TurboVLA's 12-action open-loop chunking. The official rollout horizons are
Spatial 220, Object 280, Goal 300, and LIBERO-10 520 action steps. Smoke runs with fewer trials still run,
but `lerobot-eval` logs why they are not benchmark-comparable and writes
`turbovla_libero_report.json` next to `eval_info.json`.

Use the unified LIBERO checkpoint and its accompanying `libero_all4_stats.json`
from a verifiable upstream release. Record the source URL or release identifier,
immutable revision when available, and SHA256 values for both files before
conversion. The checkpoint does not embed this provenance, so do not infer it
from a filename alone.

Benchmark values are intentionally blank until a full GPU run completes. Fill
these fields only from a run that satisfies the contract above:

## Validation

The released LIBERO checkpoint at upstream revision
`cb5300544693013164c4bb251a13036002a55c81` was converted with checkpoint SHA256
`d031ad7be05a2f5d04afb3194ed26b0cb46083685edee7a5e145078a37d26bab` and
statistics SHA256 `b6a26530cceee6748481995067bfa5570a48a4d22990730dc187fbfa1cc24827`.

| Validation | Result |
| --- | --- |
| Strict conversion | 672 tensors loaded and mapped; 0 tensors ignored |
| Vision input contract | Passed with pinned DINOv3 revision `5931719e67bbdb9737e363e781fb0c67687896bc` |
| Hardware | NVIDIA A100-SXM4-40GB, CUDA 13.0, PyTorch 2.14.0+cu130, bf16 AMP |
| Model-only latency | 62.46 ms mean, 62.37 ms median, 63.61 ms P95 across 50 iterations |
| Model-only peak VRAM | 0.835 GiB allocated; 0.916 GiB reserved |
| LIBERO Spatial smoke evaluation | 9/10 successes over one episode for each Spatial task |

Model-only latency uses batch size 1, two normalized 256x256 RGB images, an
8-D state, and one LIBERO instruction. It excludes image processing, rendering,
simulator time, action-queue reuse, and host-to-device transfer.
