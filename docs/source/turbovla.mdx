# TurboVLA (experimental)

TurboVLA is an experimental native LeRobot policy. The integration provides
model loading, serializable processors, strict conversion of upstream
checkpoints, and fresh training on a LeRobot dataset. RoboTwin is not a
validated release path.

## Installation

```bash
pip install "lerobot[turbovla,libero]"
```

For checkpoint conversion, the processor contract, supported inputs, and
provenance requirements, see the [TurboVLA policy README](./policy_turbovla_README.md).

## Evaluation

Evaluate converted checkpoints through the standard `lerobot-eval` command.
Run one suite per invocation because each suite has a distinct rollout horizon.

```bash
lerobot-eval \
  --policy.path=/path/to/converted_turbovla_libero \
  --policy.device=cuda \
  --policy.precision=bfloat16 \
  --policy.use_amp=true \
  --policy.n_action_steps=12 \
  --env.type=libero \
  --env.task=libero_spatial \
  --env.obs_type=pixels_agent_pos \
  --env.control_mode=relative \
  --env.init_states=true \
  --env.fps=20 \
  --env.episode_length=220 \
  --env.observation_height=256 \
  --env.observation_width=256 \
  --env.camera_name=agentview_image,robot0_eye_in_hand_image \
  --env.max_parallel_tasks=1 \
  --eval.n_episodes=50 \
  --eval.batch_size=1 \
  --eval.use_async_envs=true \
  --seed=7 \
  --output_dir=outputs/turbovla_libero_spatial
```

Use the same command for the remaining suites, changing the task, horizon, and
output directory:

| Suite | Horizon |
| --- | ---: |
| `libero_spatial` | 220 |
| `libero_object` | 280 |
| `libero_goal` | 300 |
| `libero_10` | 520 |

> [!WARNING]
> Released TurboVLA weights target simulation. This integration does not claim
> real-robot support, safety, or checkpoint redistribution rights. Publish
> benchmark results only with their checkpoint, environment, hardware, seed,
> and trial-count provenance.

## Training a custom robot dataset

For a fresh `--policy.type=turbovla` run, TurboVLA derives its camera names,
camera resolution, state dimension, and action dimension from the dataset
metadata. Do **not** provide `--rename_map`: the original dataset camera names
are saved in the resulting checkpoint and used again at inference time.

```bash
lerobot-train \
  --policy.type=turbovla \
  --policy.device=cuda \
  --policy.precision=bfloat16 \
  --policy.use_amp=true \
  --dataset.repo_id=your-org/your-dataset \
  --dataset.root=./your-dataset \
  --output_dir=outputs/turbovla-custom \
  --job_name=turbovla-custom \
  --batch_size=8 \
  --steps=20000
```

The dataset must expose one `observation.state` vector and one `action` vector,
plus one or more RGB cameras. Cameras may use different source resolutions; the
custom processor resizes them to the configured square DINOv3 input (256×256 by
default). A single run uses one fixed state/action schema. Train separate
checkpoints for robots with different schemas; heterogeneous embodiment padding
is not implemented yet.

The fixed `libero` and `robotwin` presets are retained for converted upstream
weights. To deliberately train using the fixed LIBERO contract, pass
`--policy.infer_from_dataset=false`.
